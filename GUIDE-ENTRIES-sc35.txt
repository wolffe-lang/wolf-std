## 2026-09-03 (sc35) — the rename, and the second gate

- THE GATE YOU CLEARED IS NOT THE ONLY GATE. sc34 refused this
  substitution with numbers because the byte PRODUCERS were missing,
  and filed the one upstream change that would make it free. The change
  landed, the numbers came out better than predicted, every signature
  moved as a rename — and the work still cannot merge, because the
  REFERENCE INTERPRETER has no `byte`. Two gates, both real, and
  clearing the first told you nothing about the second. When a sprint's
  blocker closes, re-enumerate the blockers rather than assuming the
  set had one member: the question "what else has to be true for this to
  ship?" costs ten minutes at the start and saves the discovery from
  arriving after the last edit.

- A BLAST RADIUS MEASURED FROM OUTSIDE THE LIBRARY IS A FLOOR, AND THE
  DEEPER THE LIBRARY THE FURTHER BELOW THE TRUTH IT SITS. The upstream
  issue counted 198 refusal sites in this repo; the same scan run here
  at the same pin found 149; the true number the rename had to touch was
  910. Nothing disagreed. A refusal inside a module aborts the program
  that imports it, so the compiler never reaches the call sites in the
  test and never reports them — the count you get is "what refuses
  today", and the count you need is "what the fix has to touch". They
  differ by the depth of the dependency graph. Measure the second one by
  fixing the modules first and re-scanning, and say which of the two any
  number you publish is.

- WHEN A RUNTIME CONTRACT BECOMES A TYPE, ITS WITNESS DOES NOT DIE — IT
  CHANGES PHASE, AND ITS NAME HAS TO FOLLOW. Ten tests here pinned a
  trap or a row that a caller could reach by spelling an element outside
  0..255. The element type holds that contract now, so the guards were
  unreachable code and the programs are refused at typecheck. Deleting
  the tests would have thrown away the record of a contract that is
  still enforced; leaving them named `..._trap.lu` would have promised
  an outcome that no longer happens. The move is: keep the program, move
  the directive to the new phase, and drop the part of the name that
  promised the old outcome. A file called `non_byte_trap.lu` that does
  not trap is a lie in the file listing, which is where people look
  first.

- A GUARD WHOSE COMMENT SAYS "THIS LEAVES WHEN X LANDS" IS A PROMISE
  WITH AN OWNER, AND THE SPRINT THAT LANDS X OWES IT. Five modules here
  carried a private 0..255 ingestion check, four of them documented as
  the module's ONE recorded constant-time exception with the words "it
  leaves with the real byte type" in the header. The type arrived. Not
  deleting them would have left five modules claiming a
  value-dependent branch they no longer have — a ct: note that
  overstates the hazard is as wrong as one that understates it, and it
  is the kind of wrong that survives for years because nobody re-reads a
  guard that still compiles. Grep your own headers for the promises they
  made about the change you are making.

- A PROBE THAT NEVER TAKES THE PATH REPORTS A FALSE HEAL, AND THIS
  REGISTER HAS NOW PUBLISHED TWO OF THEM. Four sprints described a
  compiler refusal as a SHAPE — "an unhandled raising call in a
  row-typed argument", then sharpened to "and the callee must consume
  it". Both were artifacts of the value the probe passed. Two programs
  that differ only in a loop bound, neither passing a literal, split:
  the one whose row is actually taken is refused and the other runs. The
  refusal was never a shape; it is an abstract interpreter declining an
  edge it reaches. Every earlier "minimal shape" ran because its probe
  chose an argument that did not raise. When you characterise a static
  refusal, vary the DATA as well as the syntax, and treat a probe that
  runs as evidence about that probe and not about the class.

- "UNSUPPORTED" CAN BE A PROPERTY OF AN EXECUTION RATHER THAN OF A
  PROGRAM, AND THAT IS A MUCH BIGGER CLAIM THAN IT LOOKS. The same
  source is accepted by the checked lane for one input and declined for
  another. A conformance ledger records one word per file per lane, so a
  corpus that only exercises the non-raising path will report the lane
  green for code the lane cannot run. If a refusal turns out to be
  path-sensitive, that is not a curiosity to note beside the trigger —
  it is the finding, because it changes what a green row means.

- THE SHAPE OF A THING YOUR RIG CANNOT RECORD IS WORTH RECORDING. This
  repository has a word for "the compilers reject statically and the
  interpreter runs" — it was built for exactly one anomaly and it is
  used again here. It has no word for the mirror image, because until
  now the mirror had never happened. The instinct on hitting that is to
  add the word so CI goes green; the honest move is to notice that the
  vocabulary is one-directional, say so, and let the red stand until the
  release that removes it. A vocabulary gap discovered by walking into
  it is a finding about the rig, and a rig extended in a hurry to make a
  wall go away is how a gate stops meaning anything.

- A LEDGER THAT IS WRONG IN A WAY ITS OWN BLOCK NOTE NAMES BEATS A
  LEDGER BENT TO BE GREEN. Faced with 181 rows whose true answer has no
  legal spelling, the three options were: write a word the grammar
  rejects, invent one, or write a word that is legal and false. All
  three end with a file that lies. The fourth is to leave the column
  alone and put the count, the cause, the module breakdown and the
  release that fixes it at the top of the file in capitals. The next
  person to open that file learns more from it than from a green run.

- THE WIN CAN BE BIGGER THAN THE CONTRACT PREDICTED, AND YOU SHOULD
  FIND OUT WHY BEFORE YOU CELEBRATE. This sprint's contract predicted
  16x -> ~2x on the native tier and the measurement said 1.00x. The
  extra factor was not the type: the upstream fix arrived with a
  PREALLOCATING producer attached, so a buffer that is READ pays no
  growth history while one that is PUSH-BUILT still pays it twice. Two
  numbers, one program, and the difference is the whole advice a caller
  needs. A better-than-expected result is a result you do not yet
  understand; measure the neighbouring shape until the gap is named.

- A CONVERSION CAST IN A DIFF IS NOT AUTOMATICALLY CEREMONY — CHECK
  WHICH DIRECTION IT GOES. Renaming this tier added 430 narrowing casts
  and 225 widening ones, which reads like a tax until you notice that
  the three modules the change was FOR took none at all: a wrapper over
  a producer needs no cast, and the casts cluster in the modules that do
  arithmetic on octets, where the language is making an operator's
  result type explicit rather than converting a representation. Count
  the casts per module before you conclude a type is expensive; the
  distribution says what the tax actually is.

- WHEN A DIFF TOUCHES 170 FILES MECHANICALLY, THE DANGEROUS EDITS ARE
  THE ONES THAT STILL COMPILE. A blanket rewrite plus a
  compiler-driven fixer will happily turn `push(256)` into
  `push(256 as byte)` — legal, silent, and zero. The audit that caught
  all eleven was one grep for a literal above the target type's range
  next to the cast. Before trusting a mechanical pass over a narrowing
  type, write down the shape of the edit that would be WRONG AND VALID,
  and grep for it; the compiler will not, and neither will the tests
  whose whole subject you just deleted.
