## 2026-08-31 (sc30) — the slice comes home

- A refusal that fires EARLY in one release hides every refusal behind
  it, so a claim about the hidden ones is a PREDICTION even when it
  wears measurement grammar. sc29 wrote `loopback_handshake`
  native-only for the byte tier (measured: `unsupported` at resolve)
  "AND the step budget" — and the budget half had never been observed,
  because the resolve refusal fired before a single evaluation step
  ran. lupin 0.1.19 resolved the byte tier and the flagship RAN: the
  full TLS 1.3 handshake — four X25519 ladders, Ed25519 sign/verify,
  the AEAD flight — evaluates inside the 50M budget (18.9s idle). The
  corpus had already sorted the classes (single-ladder x25519 rows ran
  under lupin since sc18; only the vector sweeps blow 50M), and the
  handshake landed with its siblings, not with the sprint's prose.
  When a lane refuses at phase N, write the phase-N+1 claims as
  predictions and re-measure them the day phase N heals.

- Declaring a row against the fix pays a SECOND time at the heal:
  sc29's byte-tier facade adopted upstream's whole-or-raise vocabulary
  verbatim while lupin still refused the builtins, so when 0.1.19
  landed the pair as the str calls' own shape, both rows flipped
  `unsupported` -> `run` at FIRST SIGHT with the sc29 bodies
  untouched — the F-0049 lesson (declare against the fix; the fix is
  then a pure addition) observed at a second address, one sprint
  instead of twenty-one later.

- A dev-stamped binary is not second-class provenance. The sc30 wolf
  is no release — trunk sat two merges past v0.2.0 — and D57's honest
  identity for that build is `0.2.0+dev.b80d239` WITH the pin clause
  (`WOLF_COMMIT=<short>` stamped at build; a plain cargo build answers
  `+dev.unknown`, names no pin, and fails doctor — measured first,
  rebuilt with the stamp). Record the FULL dev identity as the
  version key and doctor gates the same pin clause a tag build offers:
  the +dev string claims no release, and that honesty is exactly what
  makes it gateable. What distinguishes acquisitions is whether the
  binary can prove where it came from, not whether a tag exists.

- The first bump where the wolf binary's own commit, the data pin and
  the doctor gate all name ONE sha (b80d239) — with lupin's
  conformance pin one merge behind (83f83bb) and the gap NAMED (the
  s130 product-match span): a trio does not have to be a single sha
  to be fully verified, it has to have every edge stated.

- Adopt a NEW binder form by probing its COMPOSITIONS first, then let
  the misfits name themselves. The sc30 struct-pattern family (14
  patterns, 8 files) probed four shapes on all three lanes before the
  first edit — plain result, dotted cross-module path, `f(x)?`, and
  `f(x) else |_| { }` — because a pattern that binds is only half the
  question; the other half is whether it composes with the row
  machinery every real site wears. Two discoveries the probes paid
  for: a DOTTED PATH names an imported struct in pattern position
  (`cert.Cert { … }`) where the struct LITERAL is E0201 across the
  same boundary — patterns and literals do not share a rule, measure
  each; and two probe files sharing a scratch directory are ONE
  module (D32 — file boundaries create no scopes), so probe dirs
  isolate or the diagnostic is about your rig, not the language.
  The adoption rules that fell out: destructure where the struct is
  BORN and name every field you pin (`..` says what the check
  deliberately ignores — rd_expect's Tlv drops `cons` because
  constructedness is not that check's business); rename fields apart
  when two destructures share a scope (`subject_cn: rsa_cn` /
  `ec_cn`); and a site where one field is read TWICE keeps its
  binding (`sub(rec.wire, 5, rec.wire.len)` — a destructure would
  force a copy the binding avoids), stated at the family commit the
  way sc28's deliberate loops were.
