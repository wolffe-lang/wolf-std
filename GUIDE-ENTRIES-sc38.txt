## 2026-09-07 (sc38) — a gate that asks a mock is not a gate

- **A PIN ARMED AGAINST A MOCK CANNOT SEE THE EVENT IT PINS.** sc36 did
  the right thing and wrote the gap down as a test whose failure message
  said, in words, "has the clause admitted its namespace? Then retire
  F-0099." When the clause DID admit it, the test stayed green. It asked
  a hardcoded two-anchor fixture, where the call under test errs for the
  gap's reason *and* for the fixture's reason, so the two states were
  indistinguishable to it. The message read like a gate; the assertion
  was `is_err()` and `is_err()` was true either way. When you pin an
  external condition, **ask the artifact the condition lives in** — here,
  the vendored registry — not a fixture you wrote to exercise the
  function. A fixture proves the function's logic. Only the real artifact
  proves the world.
- **Test the assertion by breaking the world, not the code.** The cheap
  check that would have caught it: before you commit the pin, ask "what
  single edit makes this fail?" If the answer is an edit to the fixture
  rather than an edit to the thing being watched, the pin watches nothing.
- **A WAIVER THAT STOPS FIRING IS A HOLE WHERE A GATE USED TO BE.** The
  same shape, one file over. A tier-waiver list only takes effect when a
  lane REFUSES; the day the lane starts running, every entry goes
  silently inert while still asserting a refusal that no longer happens.
  Twice in this repo's history the list emptied because a human noticed
  at a bump. Count the firings and red on any entry that never fired —
  then the list retires itself and tells you which release healed it.
- **AN EXIT CONDITION IS A PROXY; RE-MEASURE, DO NOT RE-READ.** A finding
  said it retired "at the first release conforming PAST commit X". The
  release that paid it conformed AT X — because X *was* the tag the
  feature shipped in, and the word "past" had been a shorthand for "has
  it been shown these calls yet". Written exit conditions drift from the
  question they stand for. When the release arrives, run the thing.
- **A ROW'S WORD CAN HOLD STILL WHILE ITS MEANING MOVES.** One lane word
  stayed `unsupported` across the bump — and underneath, "has never been
  shown this call" became "declines it by name, for a stated reason, in
  the other machine's own words". A ledger diff shows nothing. Nothing
  will ever show it. Write it down at the row, or it is lost.
- **PROSE IS WHAT NO GAUNTLET READS.** A doc clause said there was no way
  to poll a listener; the call that polls it had been sitting thirty
  lines below it, in the same file, for a whole sprint. No test could
  fail. A consumer found it by writing a server against the sentence. If
  a clause makes a claim the library can contradict, **lint the clause**:
  the phrases it must never say again, and the ones it must keep. It is
  an unusual thing to test and the alternative is it rotting twice.
- **CLASSIFYING A DELTA "BEHAVIOURAL" DOES NOT EXCUSE YOU FROM THE
  REGISTRY DIFF.** A predicted +1 anchor measured +2: the behavioural fix
  had *also* published a new clause. Categories are for reasoning about
  risk, not for deciding which measurements to skip. Diff the key sets
  both ways, every time, whatever you think the change was.
- **VERIFY THE MACHINE, NOT THE PARAGRAPH.** A release's pairing line
  named an older sibling than the one installed, because the sibling
  shipped after the tag was cut. Both statements were true and only one
  described the box. Read `--version`; a brief is a hypothesis.
