## 2026-09-09 (sc40) — vendor the sentence, not the copy of it

- **A CONSTANT THAT MIRRORS A SENTENCE SOMEWHERE ELSE IS A DEFECT WAITING
  FOR A HUMAN TO NOTICE.** `REGISTERED_NS` followed `[conf.anchor.ns]`
  by whoever bumped the pin remembering to look. Four gates already
  guarded it, and every one asked the anchor REGISTRY — what the pin
  publishes — which is a different question from what the clause
  REGISTERS. Nothing could see a clause that moved without publishing.
  `test` sat reserved upstream and uncarried here for seven weeks inside
  that blind spot, because a reserved namespace publishes no anchors for
  a registry gate to have an opinion about. The fix is not a better
  reminder: vendor the SENTENCE as data beside the registry, verify it
  byte-identical at the pin, and set-diff the copy against it both ways.
- **Ask what artifact the answer lives in, then read THAT one.** The
  registry and the clause are both upstream data at the same pin and
  they answer different questions. Four guards that all read the same
  artifact are one guard with four names. Count your gates by the
  ARTIFACTS they interrogate, not by their number.
- **Give every parser a negative control.** A parse that silently
  matches nothing makes every set-difference vacuously empty, and a
  green suite says so with confidence. The control asserts the parse's
  SHAPE (at least twelve registered, at least fifteen reserved, `gram`
  and `test` present) rather than its contents, so an admission does not
  have to edit the test that proves the test works.
- **Capture the red in every direction the gate claims to cover.** Four
  assertions, four deliberate breakages: a name added here the clause
  lacks, a name the clause adds this file lacks, and the same pair for
  the reserved list. A gate that has fired on a real event is a fact; a
  gate that has never fired is a hypothesis about your own code.
- **AN ISSUE'S PREMISE IS A CLAIM ABOUT A DATE, NOT ABOUT NOW.**
  wolf-std#10 said five namespaces behind, its own correction said one,
  and the answer at v0.2.8 was zero — two sprints had closed it while
  the text sat still. Do not arbitrate between two prose sources about
  the state of an artifact. Read the artifact, then say which of them
  was describing which day. What survived the staleness was the issue's
  SECOND ask, the durable one, and that is usually where the work is.
- **STATE A DEFAULT OR YOU HAVE A POSTURE, NOT A CONTRACT.** TCP_NODELAY
  is on for every stream the runtime hands out. A wrapper that never
  mentions it leaves callers guessing; one that exposes the setter
  without saying what the OTHER direction is for is a setter nobody
  should call. Write both: the default, and the shape of the program
  that wants the opposite.
- **DO NOT DECLARE A ROW THE TYPE SYSTEM HAS ALREADY ELIMINATED.**
  `net_write_bytes` keeps `invalid` because it is still true of an FFI
  caller. `net_writev` takes `List[List[byte]]` and declares `{closed,
  io}`, because no typed caller can reach `invalid` through it. A row set
  is a promise about what a caller may have to handle; padding it makes
  every handler wider than the truth.
- **A POSITIONAL ROW FROM A BUILTIN GETS NAMES AT THE LIBRARY BOUNDARY.**
  `fs_fstat` answers `[kind, size, modified_ms]`. `got[1]` and `got[2]`
  are the same type and swap silently; `st.size` and `st.modified_ms`
  cannot. The test is confusability, not tidiness — and keep the FIELD
  units identical to the neighbouring call the value will be compared
  against, or you have shipped a second vocabulary wearing the first
  one's name.
- **WHEN A HOST DIFFERENCE LIVES IN A NEIGHBOURING CALL, SAY SO, AND
  ASSERT THE DISJUNCTION.** `fs.fstat`'s directory `kind` is unreachable
  on windows because `fs.open` refuses to open a directory, not because
  `fstat` differs. A witness asserting the unix answer is red on windows
  for something that is not a defect; one asserting the windows answer is
  red on the hosts you serve most. Assert what a portable program may
  rely on — one of the two happens, neither is a trap — and write the
  branch into the header.
- **A MATCHED PIN BUYS REACH ONLY WHERE THE CAPABILITY EXISTS.** With
  every pin on one commit, sc40 predicted all three of its wrappers
  would run on all three lanes. The two net ones did. The fs ones did
  not, and the reason was never a release date: the reference machine
  has no filesystem by design. Version alignment removes DATE-shaped
  refusals. It does not remove POSTURE-shaped ones, and the two wear the
  same word in a ledger.
